## Metrics with an external source of record

| Metric | Role in the project | Cite | Defensive definition (formula + plain reading + boundary) |
|---|---|---|---|
| **Macro-F1** | Primary metric for next **category** | `[new] sokolova2009measures` | Unweighted mean of per-class F1 (harmonic mean of precision and recall). Reads as "average per-class quality, every class counting equally." Boundary: insensitive to class frequency, so it does not reward a model that only serves the majority class. |
| **Acc@10** | Primary metric for next **region** | (convention; no origin DOI) | Fraction of cases where the true region is in the model's top-10 ranked list. Reads as "how often the right region is among the ten best guesses." Boundary: a ranking metric, not calibration; says nothing about the probability mass on the true region (that is MRR's job). |
| **MRR** | Primary metric for the joint Δm scoreboard | (convention; no origin DOI) | Mean reciprocal rank of the true region. Reads as "on average, one over the position of the right region." Boundary: rewards better-ranked predictions even where raw top-10 is unchanged. |
| **Δm (relative multi-task performance drop)** | Joint MTL scoreboard | **`[new] maninis2019attentive`** | Average relative per-task change vs the dedicated single-task baselines: Δm = (1/T) Σ_i (−1)^{l_i} (M_{m,i} − M_{b,i}) / M_{b,i}, where l_i flips sign for metrics where lower is better. Reads as "the average percentage by which the joint model trails (or leads) its single-task references across tasks." Boundary: it is a *relative* aggregate against a chosen baseline; the baseline must be named (here, the dedicated single-task model), and a positive Δm is a lead only if each per-task change is itself significant. |

## Reference points and baselines (floors and ceilings)

| Reference point | What it is | Cite / status |
|---|---|---|
| **Majority-class floor** | Always predict the most frequent class (for next category, the Food-dominant class). Any learned model must clear it. | Textbook convention; defensive definition, no external citation. |
| **Markov-1 floor** | Predict the next item from the first-order transition frequencies of the training partition. | `[new] gambs2012mmc` (mobility Markov chain; targets next **place**). For next category/region the project uses the same one-step-transition idea as a floor; define defensively and cite Gambs for the mobility-Markov origin. |
| **Predictability ceiling** | The entropy-based upper bound on how predictable human movement is. | `song2010limits` (already cited). **Verified firsthand (PDF this session):** the paper finds a **93% potential predictability** in user mobility across the whole user base. NOTE: the "80%" sometimes paired with it is NOT a second population figure; it is an illustrative low-predictability user (Pmax=0.2 chooses randomly ~80% of the time). Quote only the 93% as the population ceiling. |
| **Dedicated single-task ceiling** | Each task's own single-task model; the reference the joint model is read against. | Project construct; defensive definition. |

## Project-specific metrics (defensive definition only, no external citation)

- **OOD-discounted Acc@10** (`top10_acc_indist` in the code): Acc@10 computed only over test cases whose true
  region was seen in training, excluding out-of-distribution targets the model could not have learned. Reads as
  "top-10 accuracy on the regions the model had a chance to learn." Boundary: the in-distribution and full-distribution
  variants differ by the OOD share (roughly 0.6–1.1% at one dataset); report which variant a number uses, because
  converting between them can shift a comparison by up to ~0.7 pp. This is a project construct with no external
  source; it needs a defensive definition, not a citation.
- **Joint checkpoint selector**: the rule that picks the single deployed multi-task checkpoint by a combined
  category+region score (rather than either task alone). Reads as "one model is chosen to serve both tasks, scored
  on both at once." Boundary: the exact combining rule is a design choice; the earlier fixed-weight-era selector is
  retired for check-in-level work and must not be described as current. Write it in prose as "the joint-score
  checkpoint selection rule," never by its repo flag name.

## Class-imbalance rationale (why macro-F1, not accuracy)

The next-category label distribution is imbalanced: the Food class alone is roughly a third of check-ins
(≈32–34% depending on dataset; source: docs/context/TASKS.md, a repo-internal count -- quote from there, do not
recompute in prose). Plain accuracy is therefore inflated by the majority class and must not be the headline; the
training pipeline counters the imbalance with class-weighted cross-entropy (weights from scikit-learn's
`compute_class_weight`, `class_weight='balanced'`). This is the argument that *justifies* macro-F1 as the primary
category metric (`[new] sokolova2009measures`). Focal loss (`[new] lin2017focal`) is the standard alternative
remedy and may be cited if 2.4 contrasts it with weighted cross-entropy; the project uses weighted cross-entropy,
not focal, so cite focal only as the alternative, not as what the project does.

## Validation protocol and significance (already in the 2.4 map)

User-disjoint (grouped) cross-validation `[new] kohavi1995crossval` + scikit-learn `[new] pedregosa2011sklearn`
(cite the API docs for StratifiedGroupKFold, added in scikit-learn v1.0/2021 -- not in the 2011 paper); paired
Wilcoxon signed-rank test `[new] wilcoxon1945` for "outperforms"; Holm correction `holm1979` for multiplicity;
TOST `lakens2017tost` for "matches" within the two-point margin.
